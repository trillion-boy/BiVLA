# 연구 진행 종합 보고서 (한글)

**주제: Frozen VLA 모델의 Training-Free 실시간 효율화 — Non-Uniform 자원 배분**
**환경: SimplerEnv WidowX-Bridge (4개 task) / 모델: UniVLA, SpatialVLA / 조건: 학습 없음, 외부 모듈 없음, 모델 가중치 동결**

---

## 한 줄 요약

"중요한 곳을 선명하게 보자(visual focus)"에서 출발했지만, 측정을 통해 **진짜 병목은 시각 처리가 아니라 액션 생성(decode)** 임을 발견했고, decode를 "싸게 만들기"는 구조적으로 한계가 있음을 확인한 뒤, **"덜 자주 부르기"(action chunk 실행)** 로 방향을 전환하여 **성공률을 올리면서 속도를 약 2배 높이는** 결과를 얻었다.

| | 시작 시점 (visual focus) | 현재 (chunk 실행, k=2) |
|---|---|---|
| 성공률 변화 | +2%p 수준 (미미) | **4개 task 평균 +13%p** |
| 속도 변화 | 거의 없음 | **약 1.9배 빠름** |

---

## 용어 미니 사전 (이 보고서를 읽는 데 필요한 것만)

- **VLA (Vision-Language-Action)**: 이미지 + 명령어를 입력받아 로봇 팔의 움직임(액션)을 출력하는 모델.
- **Latency**: 로봇이 한 번 움직이기 위해 모델이 계산하는 데 걸리는 시간. 낮을수록 로봇이 부드럽고 빠르게 반응한다.
- **Training-free**: 모델을 다시 학습시키지 않고, 추론(사용) 시점의 동작만 바꿔서 개선하는 방식. 우리 연구의 대원칙.
- **한 control step의 3단계**:
  1. **인코딩**: 이미지 한 장을 모델이 이해할 수 있는 토큰들로 변환.
  2. **Prefill**: 모델(LLM)이 이미지 토큰 + 명령어를 한꺼번에 읽는 과정. 한 번에 병렬로 처리되어 빠르다.
  3. **Decode**: 액션을 나타내는 토큰들을 **하나씩 순서대로** 생성하는 과정. 앞 토큰이 나와야 다음 토큰을 만들 수 있어서 병렬화가 안 되고, 그래서 느리다.
- **토큰**: 모델이 다루는 정보의 최소 단위. 이미지도 토큰 뭉치로, 액션도 토큰 몇 개로 표현된다.

# Phase 1. 시각(visual) 축 — "중요한 곳만 선명하게 보면 빨라질까?"

## 1-1. 출발점: 멘토님의 method

멘토님이 설계한 구조는 **test-time controller**다:

> 명령어와 이미지를 보고 → task 종류를 파악하고 → 현재 단계(잡기/놓기)를 확인해서 → "지금 추가로 집중(extra visual focus)이 필요한가?"를 판단 → 필요하면 중요한 영역만 선명하게, 나머지는 거칠게 처리 (AutoGaze 참고)

직관은 명확하다: 사람 눈도 중심만 선명하게 보고 주변은 흐리게 본다(foveation). 배경 처리에 쓰는 계산을 아끼면 빨라지고, 중요한 곳에 집중하면 정확해질 것이다.

실제 결과(멘토님 실험, UniVLA): 성공률 82.29% → 84.38% (+2.09%p), 속도는 거의 동일. **정확도에 약간의 도움은 있지만 기대만큼 크지 않았다.**

## 1-2. 우리가 이어서 시도한 visual 축 방법들

같은 방향에서, 외부 모듈(GroundingDINO 같은 별도 detector) 없이 할 수 있는 방법들을 실험했다.

**(a) FastV — UniVLA (시각 토큰 잘라내기)**
모델이 스스로 계산하는 attention(주의) 점수를 보고, "모델이 별로 안 보는" 시각 토큰들을 중간에 버리는 방법. 계산량이 줄어드니 빨라질 것으로 기대했다.
→ 결과: 성공률 100% → 75% → 38%로 **크게 붕괴**, 속도는 **거의 그대로**. 최악의 조합.

**(b) ToMe — SpatialVLA (비슷한 토큰 합치기)**
서로 비슷한(대부분 배경인) 시각 토큰들을 중간 단계에서 합쳤다가, 마지막에 다시 원래 개수로 복원하는 방법. 모델 뒷부분이 받는 입력 형태가 안 바뀌어서 안전하다.
→ 결과: 성공률 **유지**(파지율은 88→92%로 오히려 상승), 속도는 **0.99배 (변화 없음)**.

**(c) Temporal caching — SpatialVLA (이전 프레임 재사용)**
연속된 카메라 프레임은 거의 비슷하니, 이미지 인코딩 결과를 2스텝에 1번만 새로 계산하고 나머지는 재사용.
→ 결과: 2스텝 재사용은 성공률 유지 + **약 4% 빨라짐** (유일하게 조금이라도 빨라진 visual 방법). 3스텝 재사용은 성공률 붕괴(54%).

## 1-3. Phase 1의 결론

| 방법 | 성공률 | 속도 |
|---|---|---|
| visual focus (멘토님) | +2%p | 변화 없음 |
| FastV | 붕괴 | 변화 없음 |
| ToMe | 유지/약간 상승 | 변화 없음 (0.99x) |
| temporal caching (2스텝) | 유지 | +4% |

**시각 쪽을 아무리 줄여도 속도가 거의 안 빨라진다.** 정확도 유지에는 성공한 방법(ToMe)도 있지만, 원래 목표였던 "latency 감소"는 전혀 달성되지 않았다. 왜일까? → 이 질문이 Phase 2로 이어진다.

# Phase 2. 측정과 깊이(depth) 축 — "시간은 실제로 어디에 쓰이는가?"

## 2-1. 프로파일링: 한 스텝을 분해해서 시간을 재보았다

로봇이 한 번 움직일 때 모델 내부에서 시간이 어디에 쓰이는지 단계별로 직접 측정했다 (GPU 시간 정확히 측정).

**SpatialVLA (한 스텝 평균 903ms):**

| 단계 | 시간 | 비율 |
|---|---|---|
| 인코딩 (이미지→토큰) | 125ms | 13.9% |
| Prefill (프롬프트 읽기) | 60ms | 6.6% |
| **Decode (액션 토큰 12개를 하나씩 생성)** | **677ms** | **75.0%** |
| 기타 | 41ms | 4.5% |

**UniVLA (한 스텝 평균 1362ms):** 인코딩 6.1% / prefill 12.6% / **decode 69.8%**

구조가 완전히 다른 두 모델(UniVLA는 VQ 토크나이저 기반, SpatialVLA는 ViT 기반)이 **약속이나 한 듯 decode 70~75%로 수렴**했다. 이건 특정 모델의 우연이 아니라, "이미지 1장 + 짧은 액션"을 다루는 조작(manipulation) VLA의 **구조적 성질**이다.

## 2-2. 이 측정이 설명해주는 것

- **Phase 1이 왜 실패했는가**: 시각 쪽(인코딩+prefill)은 전체의 **19~20%뿐**이다. 이걸 완벽하게 0으로 만들어도 최대 20% 빨라지는 게 한계인데, 실제로는 그마저도 어렵다. 반면 decode(70~75%)는 시각 토큰을 줄여도 거의 영향을 받지 않는다.
- **AutoGaze는 왜 성공했는가**: AutoGaze는 긴 **비디오** 질의응답 모델이다. 비디오는 시각 토큰이 수천~수만 개라서 인코딩이 병목이고, 토큰을 줄이면 진짜 빨라진다. 조작 VLA는 이미지 1장(~256토큰)뿐이라 비용 구조가 정반대다. **같은 아이디어가 도메인에 따라 통하지 않는 이유를 정량적으로 규명한 것.**

## 2-3. 그럼 decode를 직접 공략하자 — 깊이(layer) 축

Decode가 느린 이유는 액션 토큰 하나를 만들 때마다 모델의 **모든 층(layer)을 통과**해야 하기 때문이다. 그렇다면 덜 중요한 층을 건너뛰면(layer pruning) 매 토큰 생성이 싸진다.

"덜 중요한 층"은 이렇게 찾았다: 층에 들어간 값과 나온 값이 거의 같으면(방향 변화가 작으면) 그 층은 별로 일을 안 한 것이다. 이 유사도를 첫 스텝에 한 번만 계산해서 순위를 매겼다 (학습 불필요).

**UniVLA 결과 (성공적):**
- 층 4개 건너뛰기: 성공률 유지/향상 + 약 1.1배 빠름.
- 더 나아가 "잡기 전엔 깊게(2개만 건너뜀), 잡은 후엔 얕게(8개 건너뜀)"로 **단계별로 바꾸는 컨트롤러**를 만들었고, task 종류(archetype)에 따라 켜고 끄는 선택적 적용까지 구현. eggplant에서 성공률 100% + 1.14배.

**SpatialVLA 결과 (실패 — 그러나 중요한 발견):**
- 26개 층 중 **가장 안 중요하다고 뽑힌 단 1개**를 건너뛰어도 4개 task 중 3개에서 성공률 하락 (eggplant 66.7→37.5%).
- 순위 방법 자체는 검증했다: 우리 순위(redundant) > 무작위(random) > 일부러 중요한 층 제거(least, 이 경우 모델이 "생성을 멈춰라"는 신호조차 못 내고 폭주) 순서로 정확히 나옴. 즉 방법이 틀린 게 아니라 **이 모델은 정말로 버릴 층이 없는 것**.

**Self-speculative decoding (실패 — 산수로 확인):**
"층 일부를 건너뛴 빠른 버전으로 초안을 만들고, 원본 모델이 한 번에 검증"하는 무손실 가속 기법도 구현했다 (출력이 원본과 100% 동일함을 보장). 하지만 초안이 원본의 85% 비용이나 되어서(층을 조금밖에 못 빼니까) 계산상 이득이 불가능했고, 실측도 1.38배 **느려짐**. 초안을 싸게 만들려면 층을 많이 빼야 하는데 그러면 초안이 엉터리가 되는 딜레마 — 위의 layer pruning 실패와 같은 뿌리다.

## 2-4. Phase 2의 결론

**"decode 한 번을 싸게 만들기"는 백본에 따라 명암이 갈린다.** UniVLA는 여유(redundancy)가 있어서 통하지만, SpatialVLA(Gemma2)는 층 하나도 아까운 모델이라 layer pruning, 토큰 pruning, speculative decoding이 **전부 같은 이유로** 실패한다. SpatialVLA에서 decode 속도를 얻으려면 완전히 다른 각도가 필요하다.

# Phase 3. 시간(temporal) 축 — "싸게 만들지 말고, 덜 자주 부르자" (돌파구)

## 3-1. 숨어 있던 발견

SpatialVLA 코드를 분석하다가 중요한 사실을 발견했다:

- 액션 1개 = 토큰 3개 (이동 1 + 회전 1 + 그리퍼 1)
- 그런데 decode는 매번 12개 토큰을 생성한다 → **모델은 원래 미래 액션 4개를 한꺼번에 계획하도록 학습되어 있었다** (action chunk).
- 그런데 기존 평가 코드(wrapper)는 4개 중 **첫 번째만 로봇에 보내고 나머지 3개를 버린 뒤**, 다음 스텝에 처음부터 다시 계산하고 있었다.

비유: 요리사가 4첩 코스를 매번 다 만드는데, 첫 접시만 내고 3접시는 버리고, 다음 접시가 필요하면 또 4첩을 처음부터 만드는 상황. 전체 시간의 75%가 이 "요리(decode)"인데 그 결과물의 3/4을 버리고 있었던 것이다.

참고로 UniVLA는 반대다: 미래 액션 5개를 예측하고 **5개를 전부 실행**한다. 즉 두 모델이 "다시 계획하는 빈도"의 **양 극단**에 고정되어 있었다 (SpatialVLA: 매 스텝 / UniVLA: 5스텝마다).

## 3-2. 구현: 만든 계획을 버리지 말고 쓰자

모델이 4개 액션을 예측하면 첫 번째는 바로 실행하고 나머지를 대기줄(큐)에 저장, 다음 스텝들에서는 **모델을 아예 호출하지 않고** 큐에서 꺼내 실행한다. k=2면 4개 중 2개 사용(모델 호출 빈도 1/2), k=4면 4개 전부(빈도 1/4). 모델의 계산은 하나도 건드리지 않는다 — 망가질 것이 없다.

## 3-3. 결과 (모두 N=24, baseline도 전부 우리 환경에서 직접 측정)

**eggplant에서 k 비교:**

| 설정 | 파지율 | 성공률 | ms/스텝 | 속도 |
|---|---|---|---|---|
| baseline (매 스텝 재계획) | 87.5% | 66.7% | 836 | 1.0배 |
| **chunk k=2** | 91.7% | **87.5%** | **457** | **1.8배** |
| **chunk k=4** | 91.7% | 75.0% | **235** | **3.6배** |

속도와 성공률이 **둘 다** 좋아졌다 (트레이드오프가 아님). 성공률이 오히려 오르는 이유: 매 스텝 재계획하면 계획이 계속 미세하게 바뀌어 팔이 떨리는데, 하나의 일관된 계획을 따라가면 궤적이 부드러워진다 (action chunking이 로봇 학습의 표준이 된 이유와 동일).

**4개 task 전체 (k=2):**

| task | baseline 성공률 | chunk k=2 | 변화 | 속도 |
|---|---|---|---|---|
| eggplant | 66.7% | **87.5%** | +20.8%p | 1.8배 |
| carrot | 25.0% | **41.7%** | +16.7%p | 1.9배 |
| spoon | 8.3% | **29.2%** | +20.9%p (통계적으로 매우 확실) | 2.0배 |
| stack | 31.3% (2회 측정 평균) | 25.0% | -6.3%p (오차 범위 내 = 유지) | 1.9배 |
| **평균** | **32.8%** | **45.9%** | **+13.0%p** | **약 1.9배** |

## 3-4. 실패 사례가 알려주는 다음 단계

유일하게 향상되지 않은 stack, 그리고 eggplant k=4의 실패들을 뜯어보면 공통 패턴이 나온다:

- **파지율은 baseline과 동일** (잡는 것은 전혀 문제없음)
- 실패는 전부 **"잡았는데 정확히 놓지 못함"** 에 몰려 있다

즉 눈을 덜 자주 뜨는(피드백이 성긴) 대가는 이동/접근/잡기에서는 전혀 없고, **정밀하게 놓는 순간에만** 발생한다. stack은 블록 위에 블록을 정확히 올려야 하는, 4개 task 중 가장 정밀한 "놓기"가 필요한 task라서 유일하게 이득을 못 본 것이다.

## 3-5. 다음 계획: 적응형 재계획 (멘토님 controller의 완성형)

여기서 멘토님의 원래 설계와 정확히 만난다. 멘토님의 controller 구조는:

> task 종류 + 현재 단계(잡기/놓기)를 보고 → "지금 정밀함이 필요한가?" 판단 → 자원 배분 결정

이 구조는 옳았다 — 우리 데이터가 증명한다 (정밀함의 수요는 정말로 단계에 따라 다르다). 다만 그 판단으로 조절했던 대상(visual focus)이 전체 비용의 14~20%라 효과가 작았을 뿐이다. **같은 controller에 새 조절 대상(재계획 빈도 k)을 연결하면**:

- 이동/접근 중: k=4 (빠르게, 피드백 성기게)
- 잡기/놓기 근처 (그리퍼 신호로 감지): k=1 (매 스텝 재계획, 피드백 촘촘히)

기대 효과: k=4의 속도(3.6배)에 k=2 이상의 성공률. stack의 하락분도 회복. 학습 없음, 외부 모듈 없음 원칙 유지. 그리고 이 controller는 UniVLA에도 대칭적으로 적용된다 (UniVLA는 반대로 "정밀 순간에 5개를 다 실행하지 말고 일찍 재계획"하는 방향의 이득).

# 결론

1. **문제의 재정의**: "시각을 효율화하자"에서 출발했지만, 측정 결과 조작 VLA의 시간은 70~75%가 액션 decode에 쓰인다. 시각 쪽 개선의 이론적 한계는 ~20%이며, 이것이 AutoGaze류 방법이 이 도메인에서 통하지 않는 이유다. (두 백본에서 동일하게 확인 → 구조적 성질)
2. **decode를 "싸게"의 한계**: 층 건너뛰기 계열은 백본 의존적이다. UniVLA에선 통하지만 SpatialVLA에선 모든 변형이 같은 이유로 실패한다.
3. **decode를 "덜 자주"의 발견**: 모델이 이미 예측하고 있던 액션 chunk를 실행하는 것만으로 4개 task 평균 성공률 +13%p, 속도 1.9배. 실패 분석 결과 비용은 오직 "정밀하게 놓는 순간"에만 발생한다.
4. **다음 단계**: 멘토님의 controller 구조(task 종류 × 단계 → 자원 배분)에 새 조절 대상(재계획 빈도)을 연결한 **적응형 재계획** — 이것이 논문의 핵심 기여가 될 것으로 예상한다.
