# LIBERO 실험 보고 — test-time 개입의 아키텍처 의존성

작성 목적: SimplerEnv에서 얻은 결과가 LIBERO에서 재현되지 않는 문제에 대한
보고와, 다음 진행 방향에 대한 자문 요청.

---

## 1. 한 줄 요약

LIBERO에서 **세 종류의 test-time 개입이 두 백본에서 정확히 반대로 작동**했습니다.
그리고 그 중 **SimplerEnv에서 이득을 주던 foveation이 LIBERO에서는 두 백본 모두에서
손해**로 바뀌었습니다. 후자가 이 보고서에서 자문을 구하고 싶은 부분입니다.

---

## 2. 실험 설계

- 벤치마크: `libero_spatial`, 10 task × 5 초기상태 = **조건당 50 에피소드**
- 백본: `openvla-7b-finetuned-libero-spatial`, `UniVLA(Emu3) / UNIVLA_LIBERO_IMG_BS192_8K`
- 하네스: 두 백본이 **동일한 평가 루프**를 공유. 개입은 픽셀 단위·규칙 단위로 동일
- 렌더링: OSMesa (CPU). LIBERO 성공 보고 즉시 에피소드 종료

개입 세 가지는 각각 다른 자원을 건드립니다.

| 개입 | forward 횟수 | forward당 비용 | 입력 정보량 |
|---|---|---|---|
| action-repeat 2 | **1/2** | 그대로 | 그대로 |
| foveation (keep 20%) | 그대로 | 그대로 | **1/5** |
| depth-prune (LLM 레이어 우회) | 그대로 | **3/4** | 그대로 |

---

## 3. 결과

| 조건 | OpenVLA | Δ | UniVLA | Δ |
|---|---|---|---|---|
| baseline | 74.0% | — | 96.0% | — |
| action-repeat 2 | 66.0% | −8.0 | **28.0%** | **−68.0** |
| foveate blur 20% | 58.0% | −16.0 | 94.0% | −2.0 |
| foveate log-polar 20% | **0.0%** | **−74.0** | 88.0% | −8.0 |
| depth-prune 4 | 56.0% | −18.0 | 86.0% | −10.0 |
| depth-prune 8 | **28.0%** | **−46.0** | 86.0% | −10.0 |
| **depth-ctrl (2→8)** | 50.0% | −24.0 | **96.0%** | **0.0** |

**세 축 전부에서 두 백본이 반대로 갈렸습니다.**

| 축 | UniVLA | OpenVLA |
|---|---|---|
| 시간 (forward 횟수) | ✗ −68 | ✓ −8 (노이즈) |
| 시각 (정보량) | ✓ −2 / −8 (노이즈) | ✗ −16 / −74 |
| 깊이 (forward 비용) | ✓ −10 | ✗ −46 |

### 3.1 latency는 깊이 축에서만 움직였습니다

foveation은 **세 조건 모두에서 latency를 전혀 줄이지 못했습니다**
(UniVLA 1882→1888 ms, OpenVLA 524→521 ms). 이미지 크기가 그대로라 시각 토큰
수가 변하지 않기 때문입니다. 프로파일러로 재보니 UniVLA 한 스텝이
**VQ 인코딩 6% / prefill 13% / autoregressive decode 70%** 구성이라,
시각 경로 전체가 약 19%가 천장이었습니다.

그래서 decode를 직접 공격하는 **레이어 우회**로 옮겼고, 여기서 처음으로
wall-clock이 움직였습니다.

### 3.2 깊이-정확도 곡선의 모양이 백본마다 다릅니다

| 우회 레이어 | OpenVLA (Llama-2, 32층) | UniVLA (Emu3, 32층) |
|---|---|---|
| 0 | 74.0% | 96.0% |
| 4 | 56.0% (1.13×) | 86.0% (1.08×) |
| 8 | 28.0% (1.30×) | 86.0% (1.29×) |

UniVLA는 **첫 손실 이후 평평**하고, OpenVLA는 레이어당 4.5~7점씩 **계속 떨어집니다**.
Emu3에는 실제로 노는 레이어 풀이 있고, Llama-2에는 없다는 뜻입니다.
(SpatialVLA/Gemma2는 이전 실험에서 **레이어 1개만 빼도** 4개 중 3개 task가
하락했습니다. → **Emu3 ≫ Llama-2 > Gemma2**)

### 3.3 phase-adaptive 컨트롤러 — 유일한 순이익

파지 전에는 깊게(2개 우회), 정책이 스스로 그리퍼를 닫은 뒤에는 얕게(8개 우회)
전환하는 컨트롤러를 붙였습니다. 전환 신호는 정책이 이미 내고 있는 그리퍼
명령이라 추가 비용이 0이고, 단방향이라 진동하지 않습니다.

**같은 latency에서 static 곡선보다 얼마나 위인지**로 평가하면:

| | 그 latency에서의 static 값 | 컨트롤러 | 이득 |
|---|---|---|---|
| **UniVLA** (1667 ms) | 86.0% | **96.0%** | **+10.0** |
| OpenVLA (445 ms) | 47.6% | 50.0% | +2.4 (노이즈) |

**UniVLA에서는 정확도 손실 0에 1.13× 가속** — 순수한 Pareto 개선입니다.
OpenVLA에서는 그냥 곡선 위의 다른 한 점일 뿐이었습니다.

이유는 3.2의 곡선 모양입니다. UniVLA는 4→8이 공짜라 파지 구간에만 깊이를
되사는 게 순이익이지만, OpenVLA는 모든 레이어가 대가를 요구해서 섞어봤자
가중평균입니다. 즉 **곡선에 평평한 구간이 있을 때만 비균등 배분이 이깁니다.**

## 4. 배제한 대안 설명

결과가 개입 때문이 아니라 셋업 문제일 가능성을 하나씩 제거했습니다.

| 의심 | 검증 방법 | 결과 |
|---|---|---|
| UniVLA는 손목 카메라가 백업이라 foveation에 강한 것 | 두 카메라 모두 열화 | 최대 8점 차이. **배제** |
| UniVLA가 애초에 이미지를 안 쓰는 것 | 양쪽 카메라 전부 검은 화면 | **0/50**. 시각 필수. **배제** |
| VQ 양자화가 왜곡을 흡수하는 것 | 시각 토큰 변화율 측정 | log-polar에서 99.4% 변함. **배제** |
| FAST 액션 토크나이저 결함 | 저자 패치 이식 후 전 조건 재실행 | 4.5% → **0.0%**. 결론 불변. **배제** |
| fovea를 엉뚱한 위치에 놓은 것 | **oracle gaze** (아래) | **배제** |
| 그냥 덜 자르면 되는 것 | depth-prune 4 | 4도 8도 UniVLA 86%. 곡선 평평. **배제** |
| 백본마다 구현이 다른 것 | 우회 로직 단일 모듈 공유, 측정 경로 2종 오차 0 확인 | **배제** |

### oracle gaze — 가장 공들인 통제

시뮬레이터에서 목표 물체의 3D 좌표를 읽어 카메라 행렬로 투영하고, **fovea를
목표물 위에 정확히** 놓았습니다. 배포 가능한 방법이 아니라 **상한선 측정용**입니다.

| OpenVLA, keep=20% | fovea 중앙 고정 | fovea 목표물 위 |
|---|---|---|
| log-polar | 0.0% | 22.0% |
| **blur** | **58.0%** | **50.0%** (z=−0.81, 차이 없음) |
| (무개입) | 74.0% | |

**blur에서는 완벽한 시선으로도 전혀 개선되지 않았습니다.** blur는 픽셀을
이동시키지 않아 열화 정도가 fovea 위치와 무관하므로, 이 행이 "위치가 원인인가"에
답하는 행입니다. 답은 아니오였습니다.

log-polar의 0→22는 극점에 샘플이 몰리는 특성상, 극점이 빈 테이블에 있던 병리적
설정에서 벗어난 것으로 해석됩니다(여전히 blur의 58%에 못 미침).

투영 좌표는 렌더 파이프라인 재현과 실제 robosuite 투영 두 방법으로 검증했고,
10개 task 전부 BDDL의 `obj_of_interest`와 대조해 목표 물체가 맞는지 확인했으며,
십자선을 그려 눈으로도 확인했습니다.

**결론: OpenVLA는 어떤 fovea 배치로도 74% → 최대 58%입니다.** 그래서 모델 자체
attention을 이용한 지시문 조건부 시선 구현은 천장이 낮다고 판단해 보류했습니다.

## 5. 걱정되는 부분 — SimplerEnv와의 불일치 (자문 요청 1)

같은 foveation 코드가 두 벤치마크에서 부호가 반대입니다.

| 백본 | SimplerEnv Bridge | LIBERO spatial |
|---|---|---|
| OpenVLA | **+18.8pp** (15.6 → 34.4) | **−74pp** (74.0 → 0.0) |
| UniVLA | **+8.3pp** (78.1 → 86.5) | **−8pp** (96.0 → 88.0) |

지금까지 알아낸 것과 배제한 것:

- **백본 문제가 아닙니다.** SimplerEnv에서 이득 본 두 백본이 LIBERO에서 **둘 다**
  손해를 봤습니다. 방향이 같습니다.
- **정책 실력 차이만으로도 설명이 안 됩니다.** "약한 정책이 배경 정리로 이득
  본다"는 가설은, UniVLA가 **baseline 78.1%로 강한데도** SimplerEnv에서 +8.3을
  얻은 것을 설명하지 못합니다.
- **fovea 위치도 아닙니다** (4절 oracle gaze).

남은 후보는 **장면 구성**입니다.

| | SimplerEnv Bridge | libero_spatial |
|---|---|---|
| 목표물 | 단일, 화면 중앙 | **똑같이 생긴 그릇 2개**, 가장자리 |
| 구분 방법 | 물체가 하나뿐 | **공간 언어로만** ("plate와 ramekin 사이") |
| 배경 | 실사, 잡동사니 많음 | 깔끔한 합성 테이블 |

foveation이 한쪽에서는 잡동사니를 지우고, 다른 쪽에서는 신호를 지우는 것으로
보입니다. 다만 이를 직접 검증하려면 **한 벤치마크 안에서 정책 실력만 바꾼 쌍**이
필요한데, 범용 `openvla-7b`에는 LIBERO 액션 통계가 없어 `unnorm_key`를 무엇으로
잡든 "약한 정책"과 "잘못된 액션 스케일"이 섞입니다. 현재 셋업으로는 분리가
불가능해 미해결로 남겨두었습니다.

## 6. 셋업 자체 검증 (정직한 자기 점검)

### 6.1 확인된 것

- 개입 플래그가 실제로 모델에 도달했는지 요약 JSON에서 자동 감사
  (`verify_runs.py`: 에피소드 수, task 수, 우회된 레이어 수, 컨트롤러 전환 횟수,
  디코드 실패율, 조건 중복 실행)
- 레이어 우회 장부는 CPU에서 27개 검사 통과. 특히 **레이어를 우회한 상태의
  캐시 사용 generate가 캐시 없는 greedy decode와 완전히 동일**함을 확인
  (여기가 틀리면 조용히 KV 캐시가 깨져 성공률로는 못 잡습니다)
- 두 백본의 레이어 선택 규칙이 동일함을 코드 공유로 보장, 중복도 측정 경로
  2종(직접 forward / forward hook)이 오차 0으로 일치함을 확인
- foveation 코드는 SimplerEnv 실험과 픽셀 단위로 동일

### 6.2 **약점 — baseline이 공개 수치보다 낮습니다**

| | 우리 측정 | 공개 수치 |
|---|---|---|
| OpenVLA `libero_spatial` | **74.0%** | **84.7%** |

n=50에서 z ≈ −2.1 (p≈0.04)로 **통계적으로 유의한 차이**입니다. 원인 후보:

1. task당 50개 초기상태 중 **앞 5개만** 사용 (참조 평가는 50개 전부)
2. 이미지 리사이즈를 참조 구현의 TF `lanczos3` 대신 **PIL LANCZOS**로 대체
   (Mesa GL 로드 이후 TensorFlow를 import하면 프로세스가 segfault로 죽어
   불가피했습니다)

**다만 모든 결론은 동일 하네스 안에서의 차이(Δ)입니다.** 같은 초기상태, 같은
리사이즈, 개입만 다릅니다. 상수 오프셋은 상쇄되고, 관심 효과 크기(−46, −74)가
이 오프셋(−10.7)보다 훨씬 큽니다.

그래도 절대값을 보고할 때는 명시해야 할 사항이고, **초기상태를 10개로 늘려
재측정하면**(약 2시간) 1번 원인인지 아닌지 바로 갈립니다.

### 6.3 아직 못 한 것

- **두 번째 suite 재현.** 모든 결과가 `libero_spatial` 하나입니다. "이 suite의
  특성 아니냐"를 아직 배제하지 못했습니다. **현재 가장 큰 구멍입니다.**
- UniVLA baseline(96.0%)을 공개 수치와 대조하지 못했습니다.

## 7. 여쭙고 싶은 것

**1. foveation을 정확도 기법으로 보셨는지, latency 기법으로 보셨는지 궁금합니다.**
저희 측정에서는 세 조건 모두 latency가 전혀 줄지 않았습니다(3.1절). 만약 latency
기법으로 의도하신 것이라면, 시각 토큰이 비용을 지배하는 설정(다중 프레임, 고해상도)
에서만 성립한다는 것이 저희 결론인데 맞게 이해한 것인지 확인하고 싶습니다.

**2. SimplerEnv ↔ LIBERO 부호 반전(5절)을 어떻게 다루면 좋을지 조언 부탁드립니다.**
현재 선택지는 세 가지로 보입니다.
   - (a) 논문 범위를 LIBERO로 한정하고 SimplerEnv foveation 결과는 싣지 않음
   - (b) 부분 설명("장면 구성이 원인으로 보이나 분리 실험은 현 셋업에서 불가")과
     함께 정직하게 보고
   - (c) 두 번째 suite(`libero_object`)에서 재현을 시도해 벤치마크 특성인지 확정

**3. 다음 우선순위 판단을 부탁드립니다.**
   - `libero_object` 재현 (약 6~8시간, 두 백본)
   - baseline 초기상태 10개로 확장 (약 2시간, 6.2절 약점 해소)
   - 새 개입 축 추가

저희 판단으로는 개입을 더 추가하는 것보다 **재현과 검증**이 급하다고 보는데,
교수님 의견을 듣고 진행하겠습니다.

## 부록: 현재까지 확보한 주장

1. **test-time 개입의 효과는 아키텍처가 결정한다** — 세 개의 독립적인 축에서
   두 백본이 매번 반대로 갈림 (각 n=50, 주요 격차 z > 2)
2. **비균등 깊이 배분이 균등 배분을 이긴다** — UniVLA에서 정확도 손실 0에 1.13×.
   균등하게는 4개든 8개든 −10
3. **그 조건까지 규정됨** — 백본의 깊이-정확도 곡선에 평평한 구간이 있을 때만.
   OpenVLA에서는 이기지 못함을 실행 전에 예측하고 확인
